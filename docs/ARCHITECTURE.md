# Architecture

## Flow

```
Option+D (Carbon hotkey, KeyboardShortcuts)
   │
   ▼
PanelController.toggle()
   │  remember previous app (NSWorkspace.frontmostApplication)
   │  SelectionReader: AX selected text ─▶ fallback simulated Cmd+C (≤120 ms, clipboard restored)
   ▼
TranslatorPanel (NSPanel, pre-built, non-activating) shows PanelView
   │  text changes ─▶ PanelModel: 250 ms debounce, cancel previous task
   ▼
EngineRouter.translate(text, pair, configuration)
   ├─ Google  : GoogleCloudEngine (v3 or v2 REST, API key header)
   ├─ DeepL   : DeepLEngine (v2 REST, free/pro host by key suffix)
   ├─ Apple   : AppleEngine (TranslationSession, installed models)
   └─ Auto    : Google ─▶ DeepL ─▶ Apple; cloud engines only with a key,
                skipped on offline / error / 1.5 s timeout (D32)
   ▼
   (before the engine, for a word or short phrase: DictionaryService ─▶ Dictionary.app entries, D35)
   ▼
TranslationResult(text, engine) ─▶ result pane + engine badge, dictionary entries below
   │
   ├─ Enter      : copy, hide
   └─ Cmd+Enter  : hide, activate previous app, simulated Cmd+V, restore clipboard
```

## Layout

```
Translator/
  App/        TranslatorApp (@main, MenuBarExtra), AppDelegate (startup, hotkey, Settings window), AppSettings (UserDefaults),
              AppFlavor (dev vs release, D33)
  Panel/      TranslatorPanel (NSPanel subclass), PanelController (show/hide, placement, previous app, resize),
              PanelModel (state, commands, debounce, keyboard routing, overlay lists)
  Views/      PanelView (SourcePane, TranslationPane, LanguageSelector, SwapButton, FooterBar), DictionaryView (D35), Overlays (LanguagePicker Cmd+P,
              ActionPanel Cmd+K), Settings/ (SettingsView tabs, SettingsWindowController)
  Engines/    TranslationEngine protocol, EngineRouter, GoogleCloudEngine, DeepLEngine, AppleEngine
  Services/   LanguageCatalog (+ Recents), FuzzyMatcher, SelectionReader (+ KeySimulator), PasteService
              (+ PasteboardSnapshot), SpeechService, DictionaryService (+ DictionaryLookup), DictionaryParser (+ HTMLTree),
              DictionaryEntry, LoginItem, AppUpdater
  Resources/  Info.plist (generated by XcodeGen from project.yml), Assets.xcassets (AppIcon, MenuBarIcon, MenuBarIconDev)
design/       menu bar icon SVG sources (D34)
TranslatorTests/  EngineTests (request/response parsing, router), ServiceTests (fuzzy, catalog, dictionary lookup, settings, model keys),
                  DictionaryParserTests (canned VIETTIEN / Oxford records)
```

## Engines

```swift
protocol TranslationEngine: Sendable {
    var id: EngineID { get }
    func translate(_ text: String, from source: Language, to target: Language) async throws -> String
}
```

- `GoogleCloudEngine` (D30): v3 `POST https://translation.googleapis.com/v3/projects/{project}:translateText` with `contents`, `sourceLanguageCode`, `targetLanguageCode`, `mimeType=text/plain`; or v2 `POST …/language/translate/v2` with `q`, `source`, `target`, `format=text`. The key travels in the `x-goog-api-key` header. Request building and response/error parsing are pure functions, tested with canned JSON.
- `DeepLEngine` (D31): `POST https://api[-free].deepl.com/v2/translate`, `Authorization: DeepL-Auth-Key`, JSON `text[]`, `source_lang`, `target_lang`. Code mapping (`sourceCode`, `targetCode`) and parsing are pure and tested.
- `AppleEngine`: `TranslationSession(installedSource:target:)` (macOS 26+). Only installed models; downloads are triggered from Settings via `.translationTask` + `prepareTranslation()`. `LanguageAvailability` tells which pairs are installed and which languages get the on-device mark in the picker.
- `EngineRouter`: `plan(for:)` turns the mode + configured keys into an ordered engine list, `shouldFallBack(after:)` decides whether Auto moves on, and cloud engines race a 1.5 s timeout (D32). All pure and tested with stub engines.
- Languages are Google codes everywhere (`LanguageCatalog`); each engine maps them to its own codes.

## Dictionary

- `DictionaryService` (actor, D35) asks Dictionary Services for the active dictionaries (Dictionary.app's enabled list and order) on every lookup. Per dictionary, `DCSCopyTextDefinition` says whether it has the term; `DCSCopyRecordsForSearchString` + `DCSRecordCopyData(record, 0)` give the records' HTML. Everything but `DCSCopyTextDefinition(nil, …)` is private and resolved with `dlsym`; without it the service falls back to the public call (first match, plain text).
- `DictionaryLookup` (pure, tested): `term(for:)` (word or short phrase, punctuation trimmed), `info(name:primaryLanguage:)` (languages from the name, else the bundle's primary language), `tiers` (bilingual for the pair, then monolingual in the source), `recordIndices` (exact headwords; the search ignores diacritics, so "the" also finds "thè").
- `DictionaryParser` (pure, tested with canned records): `HTMLTree` is a forgiving HTML parser (some records aren't well-formed XML). Oxford records are read by class (`hw`, `ph`, `se1`/`pos`, `msDict`/`df`, `ex`, `subEntry`, `etym`); VIETTIEN-style `<pre>` records line by line (`m`, `lt`, "◦", `<li>` + `<font>`, `z4` idioms, `fi`/`thn`/`bk` extra headings). The result is a `DictionaryEntry`: headword, pronunciations, sections (`main` part of speech, `phrase`, `extra`) of senses with labels and examples.
- `DictionaryView` renders it: badge per part of speech, numbered senses, examples on a quote bar with the translation in the accent color, `preview(rows:)` until "Show More".
- `PanelModel.translateNow` starts the lookup in its own task next to the engine; it usually lands first. `warmUp()` at launch loads the dictionaries off the main actor.
- Click a word (D36): `TranslatorPanel.sendEvent` marks a left mouse-down (`PanelModel.lastInputWasClick`), a key-down clears it. `SourceEditor` reports selection changes to `PanelModel.sourceSelectionChanged`, which after a click looks up `DictionaryLookup.word(in:selection:)` (the selected word or phrase, else the word at the caret). Once it has entries, `PanelController.highlightSource` marks the word with a background rendering attribute on the editor's `NSTextView` (not part of the text; cleared on edits) and `revealDictionaryToken` makes `ResultPane` scroll to the entries. Text changes and programmatic select-alls reset the click flag.

## Panel

- Built once in `applicationDidFinishLaunching`, hidden with `orderOut`, shown with `makeKeyAndOrderFront` (no app activation) on the hotkey path (D4).
- `.nonactivatingPanel`, `.floating` level, `canBecomeKey = true`, joins all Spaces and full-screen apps.
- Esc clears the input, a second Esc dismisses. Click outside dismisses unless pinned, via `resignKey` and a global mouse-down monitor installed while visible (D5).
- Position (D37): `PanelPlacement` (pure) turns the size, the screen's visible frame and `AppSettings.panelOffset` into a frame, and snaps a frame onto the guides. `TranslatorPanel.sendEvent` moves the panel itself when a mouse-down lands on a view whose `mouseDownCanMoveWindow` is true (a window-server drag would let macOS tile it); each step goes through `PanelController.drag(to:)`, which snaps and shows `SnapGuides` (a click-through window with dashed lines, below the panel). Mouse-up stores the offset.
- `HUDWindow`: a click-through pill ("Copied to Clipboard") near the bottom of the screen after copy / paste-back (D7).
- `NSGlassEffectView` is the panel's content view (Liquid Glass, rounded corners); the SwiftUI `PanelView` sits inside it in an `NSHostingView` (D12). Controls inside are plain (Raycast look): no glass buttons, two tinted cards, language selector as text + chevron in each card header.
- Keyboard: `TranslatorPanel.sendEvent` hands every key-down to `PanelModel.handleKey` first. It consumes Esc, Enter, Cmd+Enter, Cmd+K/P/Shift+P/./D/, and, when an overlay is open, arrows and Enter; everything else reaches the SwiftUI text editor (Shift+Enter inserts a newline).
- Overlays (`LanguagePicker`, `ActionPanel`) are SwiftUI views over the panes, bottom-right; their list state (`overlayQuery`, `overlayIndex`) lives in `PanelModel` so keys and clicks share one path.
- Previous app + selection: on the hotkey path the AX read is synchronous; if the focused element has no selection attribute, a simulated Cmd+C runs **before** the panel takes key focus (bounded to ~120 ms, clipboard restored), otherwise the keystroke would land in the panel.

## Storage

- `UserDefaults` only (D26): language pair, recents, engine mode, Google API key + API version + project ID, DeepL API key, layout, panel size and position offset, menu bar toggle, dictionary toggle. Hotkey stored by `KeyboardShortcuts`; launch-at-login state read from `SMAppService`; Sparkle keeps its own.

## Updates

- Sparkle 2 (`SPUStandardUpdaterController`), feed `https://github.com/betty2310/translator/releases/latest/download/appcast.xml` (D21). Release builds are signed with the self-signed certificate (D16); the appcast is EdDSA-signed in CI.
